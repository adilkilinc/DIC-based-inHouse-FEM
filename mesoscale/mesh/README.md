# Base meshes

Mesh-only Abaqus decks — nodes, elements and the grain partition, no materials
and no boundary conditions. These are the `<case>_base.inp` files that
`inp_io.build_problem()` reads; the `<job>.inp` files carrying materials and BCs
are outputs, regenerated by `gen_inp_meso.py`.

The layout below is the one `meso_config.py` expects, so pointing
`MESO_CASES_DIR` here is all that is needed:

```bash
export MESO_CASES_DIR=/path/to/repo/mesoscale/mesh
export MESO_MESH_KEY=fine_no_twins
```

| Mesh | File | Elements | Grains |
|---|---|---:|---:|
| `fine_no_twins` | `2_fine_mesh_no_twins/1_inp/fine_no_twins_base.inp` | 90,560 | 244 |
| `moderate_no_twins` | `4_moderate_mesh_no_twins/1_inp/moderate_no_twins_base.inp` | coarser, same grains | 244 |

`fine_no_twins` is the verification case reported in the documentation.
`moderate_no_twins` is the same 244 grains on a coarser mesh, useful for a fast
pass.

## Not included

The twinned meshes are too large to distribute in git — `fine_twins` is 36 MB
with 1447 grains and 584,987 elements, `moderate_twins` is 18 MB. They are part
of the dataset release rather than the code repository.

Also not included: the segmentation maps, the DIC displacement fields and the
extracted pixel grids that `MESO_THESIS_ROOT` points at. The chain needs those
for a real solve; `selftest.py` builds a synthetic stand-in so the plumbing can
be exercised without them.
